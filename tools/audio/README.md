# 음원으로 악보 만들기 (audio → score) — engine, data, evaluation

JSE listens to an audio file (MP3, M4A/AAC, WAV, OGG/Opus, FLAC, WebM audio …) and writes an editable score:
melody (singing, one instrument) on one staff, or polyphonic/piano music on a grand staff, with tempo, time
signature, key signature, ties, rests, triplets (optional) and chord symbols (optional). Everything runs on the
device (browser, Windows/Electron, Android WebView) — no server, nothing is uploaded.

```
file ─ decode (WebAudio decodeAudioData → OfflineAudioContext 22050 Hz mono; WAV parser fallback)
     ─ Basic Pitch network (Spotify, Apache-2.0) in a pure-JS graph interpreter + WebAssembly-SIMD conv kernel,
       2-s windows spread over a worker pool → note / onset posteriorgrams (88 keys, 86 frames/s)
     ─ notes: melody = Viterbi pitch tracking with continuity · piano = Basic Pitch decoding (tuned thresholds)
     ─ tempo (autocorrelation + tempo-octave chooser) → beats (dynamic programming, follows rubato)
     ─ metre (4/4 · 3/4 · 6/8 auto, or forced) + downbeat/pickup · key signature (learned naive Bayes)
     ─ quantisation (16ths or 8ths, optional per-beat triplets) → staves (treble, or grand staff split near C4)
     ─ ScoreDoc: ties across barlines, rests, key-aware spelling, chord symbols (measure.chords) → editor
```

## Engine details

* **Interpreter**: executes the 500-node graph exactly (CQT front end included). Verified against
  basic-pitch-ts reference outputs: max abs diff ≤ 3.7e-3 on all three heads (the reference test tolerance is
  5e-3; the residual comes from the int16 fixture audio), and the decoded notes of the C-major MP3 reproduce
  `poly.json` / `poly.nomelodia.json` note for note (≤ 2 frames timing — different MP3 decoders).
* **Speed**: `conv2d_1` (3×39×8×8 over 172×264) is 65 % of the MACs. The WASM kernel splats one input value and
  updates two f32x4 accumulators per weight row: plain JS 860 ms/window → 110 ms/window (≈9 GMAC/s, one thread).
  Windows are independent, so `engine.js` splits them over `min(4, cores−1 or cores)` workers.
* **Timing** (this 2-vCPU VM): 4-minute stereo 44.1 kHz MP3 in Chromium — decode 0.85 s, network 9.7 s with
  2 workers (16.8 s with 1), score 0.29 s, re-quantise 0.12 s. Node, one thread: 240 s audio → 13.1 s.
  Plain-JS fallback (no WASM SIMD): ≈27 s per minute of audio.
* **Frame times**: unwrapped frames are not equally spaced (each 2-s window keeps 142 frames for 141.27 frames of
  audio); `frameTime(k)` gives the exact time so long songs do not drift (basic-pitch-ts' approximation is kept
  as `modelFrameToTime` for fixture compatibility).

## Score-ification (`transcribe.js`)

* **Mode**: 자동 decides from the polyphony of the decoded notes after removing overtone "ghosts" (notes an
  octave/twelfth above a louder simultaneous note); threshold 1.6 fitted on the train split (melodies ≤ 1.44,
  piano ≥ 1.76; train 100 %, dev 98.7 % correct).
* **Melody**: Viterbi over 61 pitch states + silence on the note posteriorgram, jump cost `a + b·|Δ|`, voicing
  cost; repeated notes split at onset peaks, vibrato glitches merged; legato gaps < ½ beat closed.
* **Tempo/beats**: onset envelope (amplitude × length, bass boost) → autocorrelation (45–220 BPM, 2nd/3rd
  multiples folded, log-normal prior) → tempo-octave chooser (×½/×1/×2 by autocorrelation, prior and note-value
  plausibility) → Ellis dynamic-programming beat tracker. Manual BPM fixes the period.
* **Metre**: compound 6/8 when onsets split beats in three (and not in two); else 4/4 vs 3/4 and the downbeat
  phase from accents (long, loud, bass note starts, harmonic change). A pickup bar (`pickup: true`) when the first
  note is before the first downbeat.
* **Key**: naive Bayes over key signatures — pitch-class profile relative to the signature's major tonic plus a
  soft prior, learned from 1,874 excerpts of the non-holdout Finale corpus; major/minor name by Krumhansl–Kessler.
* **Spelling**: per note the (step, alter) closest to the key's centre on the line of fifths (F♯ in G, B♭ in F,
  G♯ in A minor, E♯ in F♯, C♭ in G♭).
* **Quantisation**: beat-relative positions snapped to 16ths (or 8ths); with triplets a beat switches to thirds
  when its onsets fit clearly better. Notes crossing barlines are tied; gaps become rests; values are split with
  the editor's own `alignedDurations` so beats stay visible.
* **Staves**: grand staff split at C4 with hand-position hysteresis (middle register follows the closer hand);
  one voice per staff (chords share an onset, a chord ends at the next onset).
* **Chords**: duration/bass-weighted chroma per half bar (4/4) or bar → maj/m/7/maj7/m7/dim/sus4 templates;
  a chord needs its root, third (or 4th) and fifth/seventh actually sounding; written only when it changes.

## Data and "training"

The network is pretrained; the data work tunes and validates everything after it, with exact ground truth.

1. `gen_corpus.mjs` — Finale pieces from `/home/claude/enigma-cache` (`enigmaToScore`), split by a hash of the
   file name 60/20/20 into train/dev/holdout (no piece in two splits). Per piece up to one **melody** item (top line
   of the first single-staff pitched part) and one **piano** item (both staves of a grand-staff part): ≤ 16 bars,
   ≤ ~30 s, random quarter tempo (melody 66–146, piano 56–130 BPM), 45 % with rubato (slow sine + random walk) or a
   final ritardando, humanised timing (σ 4–6 ms) and velocity. Ground truth: sounding notes (s) + written score
   (measure, tick, quarter position, ties) + beat times. 194 items (train 40, dev 79, holdout 75).
2. `synth.py` (numpy) — timbres: piano (inharmonic partials, two detuned strings, per-partial decay, hammer,
   damper), e-piano (FM tine), organ (drawbars), strings (saw + delayed vibrato), voice (formant-filtered
   harmonics, onset scoop, vibrato, breath), flute, clarinet. Augmentation: synthetic room IR (RT60 0.25–1.35 s,
   wet 8–33 %), white/pink noise at 22–42 dB SNR, MP3 round trip at 64–192 kbps (re-aligned by
   cross-correlation), gain. 
3. `run_net.mjs` caches posteriorgrams (uint16) so tuning never re-runs the network.
4. Tuning: `eval.mjs --tune` coordinate descent over `tune_grid.json` on **dev** (objective: note F1 + score-level
   notes + ½ measure F1 + small tempo/key/metre terms, averaged over melody and piano). Symbolic training on the
   non-holdout corpus (no audio): `train_symbolic.mjs` (key model, 1,874 excerpts) and `train_tempo.mjs`
   (tempo-octave weights, ~1,800 simulated performances); choices were confirmed on train+dev audio.
   The holdout split was only evaluated, never tuned on.

Regenerate (≈25 min on 2 CPUs; data goes to `tools/audio/corpus/`, git-ignored):
```bash
nice -n 10 node tools/audio/gen_corpus.mjs --per 40 --train 20
nice -n 10 python3 tools/audio/synth.py tools/audio/corpus
nice -n 10 node tools/audio/run_net.mjs tools/audio/corpus
node tools/audio/eval.mjs --split holdout --report tools/audio/eval_report.md      # --rows for per-item lines
node tools/audio/eval.mjs --split dev --tune --json /tmp/tuned.json                  # parameter search
nice -n 10 node tools/audio/train_symbolic.mjs && node tools/audio/train_tempo.mjs   # key model, tempo octave
```

## Results (holdout: 40 melody + 35 piano excerpts from pieces never used for tuning)

Melody items are transcribed in melody mode, piano items in piano mode. Note F1: onset ±50 ms and exact pitch
against the sounding notes. Score-level: written onset position (quarters, after the best global shift) and pitch
both right; *rhythm* = position right; *measure F1* = per-bar F1 of (position, pitch); *exact* = bars written
completely right. Tempo is right within ±4 % (×2: octave errors forgiven). Key = key signature. Metre = 4/4·2/4·2/2
vs 3/4 vs compound class.

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| melody | 40 | 93.8 | 92.7 | **92.9** | 60.0 | 87.5 | 62.5 | 75.0 | **57.2** | 70.3 | 71.6 | 56.9 | 44.0 |
| piano | 35 | 81.3 | 90.8 | **84.2** | 80.0 | 100.0 | 94.3 | 82.9 | **74.9** | 87.7 | 79.9 | 65.2 | 10.8 |

## Limitations

* Full band / pop mixes: only the most prominent line is taken (approximately) — the UI says so. Drums and other
  unpitched sounds are ignored. Lyrics are not transcribed.
* One voice per staff: sustained notes under moving lines are shortened to the next onset; piano bars are rarely
  completely right (exact 11 %) although 91 % of written notes are right when the tempo is right.
* Tempo octave (½×/2×) is the main error; metre is 4/4, 3/4 or 6/8 only (others can be set in the editor); tempo
  changes inside a piece are tracked as rubato, not written as new tempo marks; swing is not detected.
* The synthetic corpus is band/school material rendered with simple synths; real instruments and voices (with
  lyrics, portamento, expressive timing) will score lower.
